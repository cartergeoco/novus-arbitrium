# Browser security setup

The app runs a Cloudflare Turnstile **Invisible** check before account sign-in, code requests, Google OAuth start, account save access, provider connection checks, turn generation, and AI flag generation. The token is verified only on the server against Cloudflare Siteverify. The app checks both the expected `browser_check` action and the request hostname, then gives the browser a signed, HttpOnly, Secure-in-production cookie for 20 minutes. Sensitive API routes reject missing or altered cookies. The check runs only after all three values are set. Until then, account and AI routes stay available. A partial setup, or a signing secret shorter than 32 characters, fails closed.

1. In [Cloudflare Turnstile](https://dash.cloudflare.com/?to=/:account/turnstile), create a **free Invisible widget** and allow the exact live hostname. Add `localhost` for local Turnstile testing. Copy its site key and secret key.
2. Generate a different 32+ character signing secret: `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`.
3. In the site's server environment, set `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`, and `BROWSER_CHECK_SECRET`. Never prefix the secret values with `NEXT_PUBLIC_`, put them in source control, or use the same value for another service. Redeploy. The check starts on the next deployment after all three values are present.
4. Try email code request, Google sign-in, provider check, and an AI flag or turn on the live hostname. Check `/api/browser-check` for `{ "verified": true }` after a successful action; it never exposes a secret. If a browser extension blocks Cloudflare's script, the action reports a verification error rather than silently bypassing the check.

The app's check limits automated requests at the application layer. It cannot tell whether a visitor is harmless, and it cannot absorb a DDoS attack. Put the live hostname behind an edge provider such as Cloudflare and enable its DDoS protection and bot management. Add edge rate limits for `/api/browser-check`, `/api/auth/email/start`, `/api/auth/email/verify`, `/api/auth/google`, `/api/auth/signin`, `/api/provider`, `/api/turn`, and `/api/flag` based on your real traffic; avoid a blanket limit on game assets or map requests. Configure Supabase's Auth rate limits as well. The site's CSP permits only Cloudflare's Turnstile script and frame in addition to its own scripts.

Official references: [Turnstile setup](https://developers.cloudflare.com/turnstile/get-started/), [server-side validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/), and [Cloudflare rate limiting](https://developers.cloudflare.com/waf/rate-limiting-rules/).
